# 单智能体 V1 执行计划

## 文档控制

- 状态：活动草案
- 目标周期：`4-6 weeks`
- 阶段：从文档到实现的交接

## 1. 目标

将规格、SDD 和 harness 整理成一份可直接指导实施的首个单智能体版本计划。

## 1.1 当前已冻结决策

- V1 必选知识输入：`txt`、`md`、`json`、`pdf`、`docx`、`xlsx`、`pptx`
- 前端技术栈固定为 `Next.js`
- 开发调试默认使用本地模型
- 本地模型调用层要求 OpenAI-compatible
- V1 访问模型固定为单租户内部登录
- V1 引用粒度固定为页码、标题路径、sheet、slide 和表格 / 单元格范围

## 1.2 编码启动前配套文档

在正式初始化代码前，实施团队应同时阅读：

1. `docs/product-specs/single-agent-v1-spec.md`

3. `docs/design-docs/single-agent-v1-workspace-layout.md`

## 2. 交付策略

按以下顺序构建：

1. 最小可用的端到端聊天闭环
2. 摄取与索引
3. 基于检索的回答
4. 管理员配置与快照
5. 评测 harness 与稳定化
6. 模型对比

这个顺序可以避免过早优化，并保持系统可度量。

## 3. 里程碑

### 第 0 周：实现准备

交付物：

- 冻结首批文件格式范围
- 冻结前端、后端、AI 运行时和本地模型开发路径
- 输出 monorepo 目录布局文档
- 输出编码前准备清单

退出标准：

- 团队对首批文件格式、技术栈和本地模型联调路径无歧义
- 工作区结构与 agent 调度方式已成文

### 第 1 周：基础

交付物：

- 初始化仓库结构
- 确认前端、后端和 AI 运行时边界
- 决定部署拓扑
- 建立本地模型联调方式
- 将聊天流程定义到接口级细节

退出标准：

- 实施团队可以基于已达成一致的接口开工
- 产品范围和服务边界不存在未解决歧义

### 第 2 周：知识摄取

交付物：

- 定义文件上传工作流
- 最终确认解析器职责
- 冻结基线切块策略
- 定义文件状态生命周期

退出标准：

- 从文件上传到 chunk 建索引的整条摄取链路已被完整说明

### 第 3 周：检索与回答

交付物：

- 定义检索流程
- 选定 reranking 策略
- 固定来源归因策略
- 定义拒答行为

退出标准：

- 端到端 RAG 路径不存在未解决的设计缺口

### 第 4 周：管理控制与版本化

交付物：

- 最终确认配置版本化行为
- 最终确认会话快照规则
- 最终确认知识删除与重建索引语义

退出标准：

- 在不牺牲可复现性的前提下，运行时可变性已被定义清楚

### 第 5 周：Harness 与质量门槛

交付物：

- 种子评测数据集规格
- 评分 rubric
- 实验矩阵
- 失败分类体系
- 发布门槛

退出标准：

- 任意模型或 prompt 变更都可以在同一 harness 下被评估

### 第 6 周：模型对比与上线准备

交付物：

- `Qwen` 与 `DeepSeek` 的对比协议
- 上线检查清单
- 未解决风险清单
- 实现启动检查清单

退出标准：

- 生产模型决策可以基于证据做出
- 团队可以在低歧义前提下开始初始化代码

## 4. 工作流

### 4.1 产品工作流

- 最终确认必要用户旅程
- 收敛受支持文件类型范围
- 定义上线验收标准

### 4.2 架构工作流

- 最终确认服务边界
- 最终确认数据对象
- 最终确认部署假设
- 建立 monorepo 与 agent 调度骨架

### 4.3 检索工作流

- 冻结初始切块策略
- 冻结基线检索栈
- 定义评测问题和失败分类体系

### 4.4 质量工作流

- 定义 graders
- 定义离线报告格式
- 定义模型决策的提升与回滚逻辑

### 4.5 工程治理工作流

- 初始化 git 与提交规范
- 提供根级统一命令入口
- 准备样例文档与种子评测集
- 建立 `agent-registry/` 机器可读清单

## 5. 需要关注的风险

- 在单智能体闭环之前过度扩展成平台特性
- 过早微调
- 对图像密集文档的解析行为定义不足
- 在检索尚未稳定前就进行模型对比

## 6. 决策日志需求

团队应在决策发生时记录：

- 选定的前端技术栈
- 开发环境与生产环境的模型服务栈
- 基线 embedding 选择
- 遗留 Office 文档是否纳入转换链路
- `pptx` notes 是否进入检索

## 7. 交接完成条件

当实施团队能够回答以下问题时，这份计划才算完成：

- 我们究竟在构建什么
- 系统如何组织
- 我们如何判断它是否有效
- 应该按什么顺序构建

如果这些问题中仍有任何一项含糊不清，那么在开始代码实现前，文档仍需修订。
