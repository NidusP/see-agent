# 单智能体 V1 本地模型服务稳定性探针设计

## 文档控制

- 状态：`implemented; real provider probe completed`
- 版本：`v1.0`
- 更新日期：`2026-08-06`
- 目的：为 A1 真实模型质量评测提供独立的 provider 稳定性与延迟证据

## 1. 背景与目标

最近的 A1 候选预检连续出现 `model_generation_timeout`。该错误只能说明真实模型调用在规定时间内没有完成，不能直接证明 scope policy、RAG 检索或回答策略错误。

本探针用于回答以下运维问题：

1. 配置的真实模型服务是否可访问，且确实提供目标模型。
2. 短文本生成在冷启动后的连续请求中是否稳定完成。
3. 结构化 JSON 生成是否稳定完成并能被解析。
4. 首次返回和完整返回分别需要多长时间，是否存在单次卡住或明显延迟尖峰。

探针只产生 provider 运行证据，不产生质量评测结论，也不能作为 Q1 发布依据。

## 2. 范围与非目标

### 范围

- 使用当前实际配置的 `LOCAL_LLM_PROVIDER`、`LOCAL_LLM_BASE_URL`、模型编号和超时值。
- 支持当前产品使用的 `ollama_native` 和 `openai_compatible` 两种真实调用协议。
- 先执行模型列表检查，再按顺序执行若干短文本请求和结构化 JSON 请求。
- 记录每次请求的协议阶段耗时、结果、稳定错误码、输出长度和模型返回的 token 统计。
- 允许将脱敏 JSON 报告写入指定路径，报告不保存模型正文、不保存服务 token。

### 非目标

- 不调用 RAG 检索、embedding、Qdrant 或 Backend。
- 不使用测试 provider、heuristic fallback、手写模型结果或重试覆盖失败。
- 不运行 A1 题库、不创建实验、不创建或发布 Agent 配置、不修改 active release。
- 不根据探针结果自动延长超时或自动选择模型。

## 3. 执行协议

每次探针运行固定记录一个 `probe_run`：

1. 读取并校验 provider、模型和正数超时值。
2. 调用模型列表接口，确认目标模型存在。
3. 执行 `N` 次短文本生成，默认 `N=3`。
4. 执行 `N` 次结构化 JSON 生成，默认 `N=3`。
5. 每次请求都使用真实 HTTP 调用，禁止失败重试；请求顺序和参数写入报告。
6. 任意请求失败时保留已完成样本，并以非零退出码结束。

结构化 JSON 请求只验证传输和协议稳定性：响应必须是非空 JSON 对象，不能把 JSON 内容当作业务答案或质量分数。

## 4. 记录字段

报告至少包含：

- `probe_version`、`run_id`、UTC 开始/结束时间。
- `provider`、模型编号、脱敏 endpoint、配置超时、重复次数。
- 每次请求的 `kind`、顺序、状态、错误码、首事件耗时、完整返回耗时。
- 非流式请求记录 HTTP 完成耗时；流式请求记录首个事件和终止事件耗时。
- 输出字符数、完成 token 数、结束原因和是否解析成功。
- 汇总的成功数、失败数、最小/中位数/95 分位耗时、首事件延迟和完整延迟。
- `fallback_used=false`、`quality_eligible=false` 和 `evaluation_purpose=provider_stability_probe`。

报告只保存用于诊断的长度和计数，不保存模型返回正文。

## 5. 通过与停止条件

### 探针通过

- 模型列表请求成功且目标模型存在。
- 所有短文本和 JSON 请求都在配置超时内完成。
- 所有响应非空且协议解析成功。
- 没有 `model_generation_timeout`、连接失败、HTTP 拒绝或流式响应中断。

### 探针失败

以下任一情况都失败并停止，不用重复请求掩盖：

- 目标模型不存在。
- 任意请求超时、无法连接、HTTP 被拒绝、响应为空或 JSON 无法解析。
- 实际 provider/model 记录不完整。

失败报告用于定位 provider 稳定性，不得解释成 A1 处置准确率或 RAG 质量结论。只有 provider 探针通过后，才允许按冻结条件重新执行 A1 非 Q1 预检。

## 6. 验收

- 单元测试覆盖 provider 参数解析、endpoint 脱敏、成功/超时/连接失败/空响应/非法 JSON。
- 本地无 provider 时仍 fail-closed，不产生成功报告。
- 真实本地运行至少包含连续短文本和结构化 JSON 两组请求，并保存一份脱敏报告。
- 既有 Runtime 全量测试、Backend 全量测试、Web 检查和 fullstack readiness 不受影响。

## 7. 2026-08-06 实际证据

真实探针报告 `provider-stability-20260806T030918424901Z` 使用 `ollama_native`、`qwen3:14b`、90 秒配置超时，执行三次短文本非流式、三次结构化 JSON 非流式和一次流式调用：7/7 成功，`fallback_used=false`，没有超时或协议错误。

- 模型列表检查为 1.147 秒，目标模型存在。
- 第一条短文本非流式调用为 57.874 秒；后两条分别为 2.738 秒和 2.499 秒。
- 三条结构化 JSON 调用分别为 8.059 秒、5.010 秒和 5.532 秒，均返回可解析 JSON 对象。
- 流式调用首事件为 1.830 秒，完整返回为 2.797 秒。
- 全部样本的完整返回中位数为 5.010 秒、95 分位为 57.874 秒。

该证据证明 provider 当时可用，但首条调用已经接近 Backend 默认 60 秒 deadline。它不是 A1 质量、Q1 实验或发布证据；不得据此延长超时、重跑已停止候选或修改 active release。
